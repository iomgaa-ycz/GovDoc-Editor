# 文档对比分类命名与最小长度过滤

## 背景

对比结果页原有三类前端文案为“完全重复 / 高度相似 / 疑似抄袭”。这些表述容易被理解为法律或事实判断，但当前算法实际输出的是三类文本匹配：

| category | 算法含义 | 展示文案 |
|---|---|---|
| `paragraph` | 跨文件完全相同的段落 | 相同段落 |
| `sentence` | 跨文件完全相同、且未被相同段落覆盖的句子 | 相同句子 |
| `similar` | SimHash 判定的近似段落对 | 近似段落 |

## 决策

1. 前端分类按钮、统计卡片统一使用“相同段落 / 相同句子 / 近似段落”。
2. 对比摘要接口新增 `min_length` 查询参数。阈值为当前滑条值 `N`，返回时过滤所有 `match.length < N` 的匹配项。
3. 过滤在后端 `/api/v1/compare/{review_id}/summary` 完成，分页与分类计数均基于过滤后的集合计算，避免前端仅过滤当前页造成数量不准。
4. 结果页保留完整 `review.json` 和 context 读取逻辑不变；长度过滤只影响 summary 匹配清单与点击入口。

## 不做

- 不把 `similar` 改成“抄袭”或“违规”类结论。
- 不重新计算对比算法；仅过滤已生成的 summary 匹配项。
- 不修改高亮 DOCX 下载内容。
