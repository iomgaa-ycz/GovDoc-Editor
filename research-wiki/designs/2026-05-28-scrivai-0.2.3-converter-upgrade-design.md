# Scrivai 0.2.3 MarkdownConverter 升级设计

## 概述

将 Scrivai 从 0.2.1 升级到 0.2.3，用 `MarkdownConverter` 单例替代已废弃的 `to_markdown()` 旧签名，实现 MonkeyOCR 双端点主力 + GLM OCR fallback 的多后端容错策略。

## 驱动力

| 因素 | 0.2.1（现状） | 0.2.3（目标） |
|------|-------------|-------------|
| `to_markdown` 签名 | `to_markdown(path, ocr_backend=, max_workers=, timeout=)` | `to_markdown(path)` 零参数，旧 kwargs 已移除 |
| 多后端支持 | 单字符串 `ocr_backend="glm"` | `MarkdownConverter` + `ConverterConfig`（多后端优先级、并发、容错） |
| DOCX/DOC 处理 | 全部走 OCR 管线 | `markitdown` 本地转换（不过 OCR，速度快） |
| 容错 | 无 | 三层：per-request retry → per-group cooldown → 自动 fallback |
| 批量 | 无 | `convert_batch()` + `on_complete` 回调 |

**升级后不改不行**——0.2.3 的 `to_markdown(path)` 不再接受 `ocr_backend`/`max_workers`/`timeout`，当前 `files.py:105-110` 会直接报错。

## 后端策略

```
MonkeyOCR (主力)
  ├─ http://100.83.164.94:7866  (并发 3)
  └─ http://100.83.164.94:7867  (并发 3)
  │   共 6 并发，连续 3 次失败后 fallback
  ▼
GLM OCR (备用)
  └─ 云端 API (并发 1)
      API key 从 .env SCRIVAI_GLM_API_KEY 自动读取
```

dispatch 模式选 `fallback`：MonkeyOCR 连续失败达阈值后自动切 GLM，而非 `overflow`（overflow 会在正常情况下就把任务分给 GLM）。

## 设计方案：DocumentStore 持有单例 MarkdownConverter

### 架构

```
govdoc.yaml  →  AppConfig.converter: dict
                     │
                     ▼
runtime.py: get_document_store()
  └─ DocumentStore(storage_root, converter_kwargs={...})
       └─ self._converter = MarkdownConverter(**converter_kwargs)
            ├─ MonkeyOCR × 2 端点 (并发 3/端点)
            └─ GLM OCR fallback (并发 1)

上层调用方（全部不改）:
  routes/documents.py  ─┐
  routes/rules.py       │── store.get_or_convert(raw_path) ──→ 同一接口
  routes/projects.py    │
  compare/service.py   ─┤
  harness/pipeline_eval ─┘
```

### 被否决的方案

**方案 B：每次 `_convert` 创建临时 MarkdownConverter**——线程池/信号量每次重建销毁，多文件场景开销大，与 `lru_cache` 单例模式冲突。

**方案 C：直接用零配置 `to_markdown()`**——无法指定后端优先级和并发数，不满足 MonkeyOCR 主力 + GLM fallback 需求。

## 变更清单

### 1. `govdoc/config.py` [MODIFY]

- `AppConfig`: 删除 `ocr_backend: str = "glm"`，新增 `converter: dict[str, Any] = Field(default_factory=dict)`
- `CompareConfig`: 删除 `ocr_backend: str = "glm"` 和 `max_concurrent: int = 1`（并发由 converter 统一管理）

### 2. `govdoc.yaml` [MODIFY]

`app:` 段：
```yaml
app:
  storage_root: ./data/storage
  database_url: sqlite:///./data/app.sqlite
  converter:
    mode: api
    dispatch: fallback
    api_backends: [monkey, glm]
    monkey_endpoints:
      - "http://100.83.164.94:7866"
      - "http://100.83.164.94:7867"
    concurrency_per_group:
      monkey: 3
      glm: 1
    max_failures:
      monkey: 3
    timeout: 600
    chunk_pages: 50
    overlap_pages: 2
```

`compare:` 段精简：
```yaml
compare:
  pdf_timeout_s: 7200
```

### 3. `govdoc/storage/files.py` [MODIFY]

- 导入：`from scrivai import MarkdownConverter` 替代 `from scrivai import to_markdown`
- `__init__`: 删除 `ocr_backend` 参数，新增 `converter_kwargs: dict[str, Any] = {}`，构造 `self._converter = MarkdownConverter(**converter_kwargs)`
- `_convert`: 改为 `md = self._converter.convert(raw)`
- 新增 `close()` 方法：调用 `self._converter.close()` 释放线程池
- 删除 `self._ocr_backend` 属性

### 4. `govdoc/runtime.py` [MODIFY]

`get_document_store()` 改为：
```python
DocumentStore(cfg.storage_root, converter_kwargs=cfg.app.converter)
```

### 5. `tests/unit/test_document_store.py` [MODIFY]

- mock 目标从 `_scrivai_to_markdown` 改为 `MarkdownConverter.convert`
- 删除 `store_with_monkey` fixture
- 删除 `test_ocr_backend_passed_through`
- 删除 `test_same_file_different_backends_cached_independently`
- 新增 `test_converter_receives_config_kwargs`：验证 kwargs 透传
- 新增 `test_close_delegates_to_converter`：验证 close 委托

### 6. `scripts/test_pdf_convert.py` [MODIFY]

改用 `MarkdownConverter` 直接调用。

### 7. `deploy/.env.runtime.example` [NO CHANGE]

`SCRIVAI_GLM_API_KEY` 已存在，无需改动。

## 不需要改的文件

| 文件 | 理由 |

| `govdoc/api/routes/documents.py` | 只调 `store.get_or_convert()`，接口不变 |
