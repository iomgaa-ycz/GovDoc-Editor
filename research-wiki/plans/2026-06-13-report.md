## 0. 状态与优先级标识

### 0.1 状态标识

| 状态 | 含义 |
|---|---|
| 架构决策 | 必须先定规则，否则后续功能会返工 |
| 需重构迁移 | MVP 已有主体能力，但正式 SaaS 版必须重构接入权限、租户、数据归属或新版交互 |
| 产品化完善 | MVP 有雏形，但正式使用体验、异常处理、可追责性不足 |
| 新增建设 | MVP 基本没有，需要正式新增 |
| 待排查修复 | 已发现异常或业务反馈问题，需要用真实数据和日志定位 |
| 运维内化 | 不作为律师端产品功能，但需要工程或运营侧具备 |
| 暂缓 | 有价值，但不放入正式版第一批范围 |

### 0.2 优先级标识

| 优先级 | 含义 |
|---|---|
| P0 | 阻塞多人正式使用、数据隔离、安全、核心闭环 |
| P1 | 明显影响律师使用效率或核心业务效果 |
| P2 | 提升管理效率、体验一致性、可维护性 |
| P3 | 锦上添花、报表增强、长期演进 |

## 7. 审核点主数据架构

### 7.1 推荐规则

| 规则 | 决策 |
|---|---|
| 共享审核点 | 由管理员维护，普通用户不能直接修改原件 |
| 个人审核点 | 创建人维护，仅影响个人未来任务 |
| 普通用户想调整共享审核点 | 复制为个人审核点后再改 |
| 管理员修改共享审核点 | 生成新版本，仅影响未来新建任务；历史任务继续引用旧快照 |
| 审查任务执行 | 创建任务时快照审核点标题、描述、严重程度、法条、关键词和标签 |
| 删除审核点 | 已被历史任务引用的只能归档，不能物理删除 |
